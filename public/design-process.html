Phase 0

The Starting Point

The simulator already existed: a browser-based N-body gravity engine running in a Web Worker, rendered in Three.js with a custom Schwarzschild lensing shader and multiple physics presets. It looked polished and ran smoothly. The problem was that several things described in the code as physically accurate were not.

The goal going into this project was to turn an impressive-looking simulation into one that could actually be defended in a technical interview — where every physics claim is cited, every number is independently verified, and the architecture decisions have explicit reasoning behind them.

The gap: Looking correct and being correct are different things. A simulation can produce beautiful orbits while using wrong algorithms — and the wrong algorithms only reveal themselves when you read the underlying physics literature carefully.
Phase 1

The Physics Audit

Every physics claim in the code was extracted and checked against a primary source — not a blog post or Wikipedia, but the actual papers and textbooks the algorithms come from. The audit covered 13 distinct claims across five physical systems.

The sources used were: GADGET-2 (Springel 2005) for the N-body integrator, Aarseth (2003) Gravitational N-Body Simulations for the adaptive timestep, Misner, Thorne & Wheeler (1973) §25.6 for the Schwarzschild photon geodesic, Hernquist (1987, 1993) for Barnes-Hut force error bounds, and Navarro, Frenk & White (1996/1997) for the dark matter halo potential.

Key finding: The code called a force approximation "Barnes-Hut" — but it was actually a single mean-field force pointing toward the system's center of mass. This is O(1) per body, not O(N log N), and it eliminates all particle-particle dynamics. A real Barnes-Hut octree had never been implemented.

Four additional claims were wrong or imprecise. Code comment section references were incorrect. The default opening angle θ was documented as 0.5 (Hernquist) but should have been 0.7 (GADGET-2's production default). The Aarseth adaptive timestep formula referenced the wrong equation in the textbook.

Two claims flagged as uncertain were resolved by writing independent benchmarks.

Phase 2

The Six Fixes

01
Barnes-Hut octree (replaces mean-field monopole)
Genuine O(N log N) 3D octree with configurable opening angle θ. Default θ = 0.7 matching GADGET-2. The old mean-field code path was deleted entirely.
02
Adaptive substep cap raised
A hard limit of 1 adaptive substep per frame (for N > 120) was preventing close-encounter resolution. Raised to 64, allowing the Aarseth criterion to run at full resolution.
03
Virial ratio Q broadcast live
Q = 2KE / |PE| was computed but never displayed. Added to the diagnostics broadcast so users can see whether the system is in virial equilibrium.
04
Opt-in virial equilibration at spawn
Random body spawn produces arbitrary Q. An opt-in flag rescales all velocities by √(|PE|/2KE) at spawn so Q = 1 exactly. Default off — preserving the interesting out-of-equilibrium dynamics as the default experience.
05
NFW dark matter halo potential
Galaxy Core preset had Keplerian orbits (v ∝ 1/√r). Added analytic NFW halo acceleration so users can toggle the halo and watch the rotation curve shift from Keplerian to flat — directly demonstrating dark matter dynamics. Source: Navarro, Frenk & White (1996/1997).
06
Image-plane photon scan mode
Photons previously spawned in a cone from the camera. Added an image-plane mode that spawns photons with uniformly spaced impact parameters perpendicular to the camera–BH axis, directly revealing the photon sphere and Einstein ring geometry.
Integration note: The physics engine uses adaptive-substep Velocity Verlet (Störmer-Verlet), which is a symplectic integrator — it conserves a shadow Hamiltonian indefinitely, preventing the secular energy drift that affects non-symplectic methods like RK4. The same integrator class (leapfrog) is used in HMC sampling in probabilistic ML frameworks (PyMC, Stan) for the same reason.
Phase 3

Verification by Independent Benchmark

Every major physics fix was validated by an independent Python script — not unit tests of the code, but independent numerical experiments that should produce the same results if the physics is correct. All scripts are in benchmarks/.

The photon deflection benchmark was the most technically difficult. Near the photon sphere (b ≈ bcr), photons can orbit the black hole multiple times before escaping, making ODE exit detection unreliable — the trajectory has a fractal boundary structure. The solution was to switch from ODE integration to the exact orbit integral formulation using scipy.integrate.quad, which avoids exit detection entirely and produces exact results.

Key principle: The benchmark scripts are intentionally independent of the simulator's own code. They re-implement the physics from first principles. If both produce the same number, that's evidence the simulator is correct — not circular validation.
Phase 4

Visual Design — Diagnosing the Rendering Bug

After the physics was verified, a visual anomaly was identified: bodies passing below the black hole showed a characteristic kink in their trail — sharp descent, a flat segment, then the path shooting back upward. Bodies above the BH looked correct. The asymmetry persisted across all accuracy modes.

The clue: Rotating the camera did not change which side the kink appeared on. The anomaly was always on the world-space bottom (−Y), not the screen-space bottom. That ruled out a rendering projection issue and pointed to a world-space displacement.

The cause: body positions and trail vertices were being displaced toward the BH using a "funnel dip" formula based on XZ-plane distance only. The displacement was always applied in the −Y world direction — correct for bodies above the BH (which get pulled downward toward it), but wrong for bodies below it (which get pulled further away from the BH, creating the kink).

The fix attempted was to change the displacement direction to point toward the BH center in 3D. But this exposed the deeper issue: the Schwarzschild lensing ShaderPass was already doing this job — correctly, per-pixel, using the actual Binet geodesic. The body displacement was redundant. Two competing visual systems were producing inconsistent results.

Decision (DD-004): Remove the body/trail displacement entirely. Physics positions are shown as raw world-space coordinates. The lensing shader is the sole source of visual warping — it was already physically correct and camera-angle-dependent by construction.

With the redundant layer removed, the remaining question was why the star lensing looked blurry. The answer: the CubeCamera used for off-screen lensed rays was only 256×256. Upgraded to 512×512. Star count increased from 5,000 to 12,000, point size from 0.7 to 1.4, and the photon ring sharpened (RING_W 0.07→0.05, RING_INT 3.5→5.0) to make the lensing effects actually visible.

The visual grid (the Flamm's paraboloid spacetime funnel) was left unchanged — it correctly visualizes the embedding diagram of the Schwarzschild equatorial plane, and its own vertex shader uses XZ-plane distance appropriately because the grid itself lives in that plane.

Phase 5

The ML Layer — Simulation as Data Generator

Rather than adding ML as a separate unrelated component, the orbit stability classifier uses the physics engine itself as the data source. 3,000 random 3-body simulations were generated using the same Velocity Verlet integrator, each labeled by outcome: stable triple (79.6%), binary + escapee (17.0%), dissolved (3.4%).

Features were extracted from the initial state — Q_init, minimum and maximum separation, mass ratio, angular momentum, specific energy, velocity spread. These are physics-informed features: they represent quantities that theoretically predict stability.

The most important result: Q_init (virial ratio at t=0) is the dominant predictive feature with ~35% Gini importance. This directly validates why broadcasting Q live in the simulator's telemetry display is the most physically meaningful diagnostic — the ML independently confirms it.

The binary + escapee class (F1 = 0.72) is the hardest to classify, which is physically expected. The binary/escape boundary is the most chaotic outcome — small changes in initial conditions can push either way — and no feature set cleanly separates it.

Design choice: Scikit-learn only, no neural network. With 3,000 samples across 7 features, gradient boosting already achieves 90.8%. A neural network would likely overfit and offer no interpretability advantage. The physics-informed features make the RF results explainable — which is the point.

What the Process Showed

🔍

Read the source

Code comments referencing papers are not the same as reading the papers. Four of 13 physics claims were wrong — not because of bad code, but because they were never verified against the original source.

📐

Verify independently

Unit tests of your own code are circular. The benchmarks here re-implement the physics from scratch. Agreement between two independent implementations is actual evidence of correctness.

🧩

Separate systems compete

The body displacement bug came from two visual systems doing the same job. The fix wasn't to make one more correct — it was to recognize the redundancy and remove one entirely.

📊

ML validates physics

The orbit classifier didn't just add ML to a physics project. Q_init emerging as the top feature independently confirmed that the virial ratio display is the right diagnostic to show users.

📝

Document for the interview

The case study and this doc were written knowing that each section would need to be explained verbally. If you can't describe a decision in two sentences, you don't understand it yet.

🎯

Specificity over coverage

Six well-understood and well-cited fixes are stronger than twelve vague improvements. Every number in this project traces back to a primary source or an independent benchmark.

Key Design Decisions

  • DD-001
    3D octree, not quadtree. Simulation is fully 3D; quadtree only works in 2D. Fast Multipole Method (O(N)) considered but deferred — overkill for N < 500.
  • DD-002
    Virial equilibration opt-in, not default. Out-of-equilibrium collapse is physically interesting and educational. Forcing Q = 1 at spawn would remove it. Users who want equilibrium can opt in.
  • DD-003
    NFW halo gated to Galaxy Core preset. Only makes physical sense at galaxy scale. Exposing it globally adds UI complexity without value in other presets.
  • DD-004
    Remove body displacement; let lensing shader be the sole visual warping system. The ShaderPass already integrates Binet geodesics per-pixel. A competing world-space displacement produces inconsistencies. One correct system beats two competing ones.
